# Creator Operating Policy

## Default autonomy
Proceed on routine, reversible work within approved scope. Persist assumptions.

## Ask creator when
- Ambiguity changes financial correctness, privacy, workflow or architecture materially.
- Scope expands materially.
- Multiple options have meaningful tradeoffs.
- Credentials, paid services or external access are required.
- A protected release or destructive operation is requested.

## Keep moving when
- One item is blocked but independent tasks are ready.
- A transient failure can be addressed within the retry budget.
- A low-risk reversible assumption can be recorded.

## Creator inputs
Classify as feature, defect, visual feedback, priority change, decision/approval or question. Persist raw and normalized input safely, impact analysis, affected spec version/tasks, approval, and verification evidence.

## Pause/resume
Pause stops new dispatch and safely handles active tasks. Resume continues from persistent state. Cancellation never deletes source changes or evidence.

## Completion
Only verified acceptance criteria count as verified progress. Show blocked/deferred separately. Successful agent exit alone does not mean the feature is verified.
